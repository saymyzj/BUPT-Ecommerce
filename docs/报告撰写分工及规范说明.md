## 2. 报告要求

### 2.1 内容要求

报告必须完整覆盖课程指导书中对“系统架构设计与生产环境演进”的核心要求，并体现本项目代码实现与架构设计之间的对应关系。

报告正文必须包含以下核心内容：

1. 本地原型架构图与数据流说明。需要画图描述本地代码中的服务组件结构、服务之间的调用关系，以及秒杀主链路的数据流转过程。
2. 核心流程时序图。需要重点展示用户发起秒杀后，Gateway、秒杀服务、Redis、RabbitMQ、订单服务、MySQL、推送服务之间的交互顺序。
3. 数据库 ER 设计图。需要展示用户、商品、库存、秒杀活动、订单、订单明细、MQ 消息日志、AI 咨询日志等基础数据之间的关联关系。
4. 技术选型依据分析。不得只罗列通用概念，必须结合本项目业务场景说明 Gateway、MySQL、Redis、RabbitMQ、SSE、LLM API 等技术的选型理由。
5. 高并发秒杀防超卖设计。需要说明为什么不能直接扣数据库库存，Redis 库存预热如何完成，Lua 脚本如何保证原子扣减，如何防止重复抢购。
6. 异步订单削峰设计。需要说明 RabbitMQ 在本项目中的作用、订单创建消息格式、订单服务消费流程、幂等设计、重试与死信队列设计。
7. 实时推送设计。需要说明订单真正落库后如何通过 SSE 向用户推送订单创建结果，以及推送失败时如何保证订单状态仍可查询。
8. AI 智能导购设计。需要说明商品上下文构造、Prompt 设计、LLM API 调用流程、缓存机制、超时失败与降级策略。
9. 正式生产环境演进方案。需要重点说明百万日活场景下的高可用设计、高并发扩容策略、消息可靠性、数据库演进、Redis 集群、RabbitMQ 集群、大模型调用优化和监控告警方案。
10. 系统测试与验收结果。需要结合 Apifox、Redis、RabbitMQ、MySQL、SSE、AI 咨询等证据说明系统链路可验证。

报告应做到图文并茂。建议至少包含以下图片：

1. 本地原型架构与数据流图。
2. 秒杀核心链路时序图。
3. 数据库 ER 图。
4. MQ 异步订单消息流图。
5. 生产环境演进架构图。
6. 必要的 Apifox、Redis、RabbitMQ、MySQL、测试页面截图。

所有图表必须在正文中被引用和解释，不能只插入图片而不说明其含义。每张图下方应写明图名，每张表上方应写明表名。

### 2.2 语言说明

报告语言应正式、清晰、准确，符合课程学业报告和工程技术文档的表达规范。

撰写时应遵守以下要求：

1. 表述应详细正式，覆盖对应小节的必要背景、设计目标、实现思路、关键流程和原因分析。
2. 内容应精准凝练，避免与主题无关的代码堆砌、流水账式实现记录或过度口语化表达。
3. 技术说明应结合本项目业务场景展开。例如说明 Redis 时，应围绕“秒杀库存高并发扣减与防超卖”；说明 RabbitMQ 时，应围绕“订单异步削峰与最终一致性”。
4. 结论性语句需要有依据。涉及架构选择、异常处理、生产演进时，应说明选择原因、解决的问题和可能的边界。
5. 不得使用夸张、不确定或无法证明的表述，例如“完全不会出错”“绝对高可用”“无限并发”等。
6. 各成员撰写风格应保持一致，统一使用第三人称或客观陈述方式，避免频繁出现“我”“我们随便实现”等口语表达。
7. 章节之间应有逻辑衔接。前文介绍的接口、数据表、Redis Key、MQ 消息字段，应与后文测试和生产演进保持一致。
8. 正文中出现的服务名、接口路径、Redis Key、MQ 队列名、数据库表名应使用项目文档中的统一命名，不得私自改名。

建议每个小节采用以下写法：

1. 先说明该小节要解决的问题。
2. 再说明本项目采用的设计方案。
3. 然后结合图、表、接口或关键字段解释具体流程。
4. 最后说明该设计对高并发、高可用、可维护性或可演示性的作用。

### 2.3 产出说明

最终报告统一生成 Word 文档，文件格式为 `.docx`。所有成员按照本说明中的章节分工分别撰写内容，最后由 A 统一合并、排版和检查。

不属于本人负责的章节，只保留标题，不撰写正文内容，避免多名成员重复书写同一内容。合并时由对应章节负责人补充正文。

Word 文档结构要求如下：

1. 第一页为封面。封面应包含报告题目、课程名称、项目名称、团队成员姓名与学号、提交日期等信息。
2. 封面后分页，第二页为摘要和关键词。
3. 摘要和关键词后再次分页，开始正文内容。
4. 正文按一级标题、二级标题、正文组织，不随意增加未编号标题。
5. 参考文献和附录放在正文之后。

Word 文档格式要求如下：

1. 一级标题：黑体，三号，加粗，居中对齐。
2. 二级标题：黑体，四号，不加粗，顶格。
3. 正文：宋体，小四，首行缩进两字符，1.5 倍行距。
4. 图的名称放在图下方，黑体，五号，居中对齐。
5. 表格名称放在表的上方，黑体，五号，居中对齐。
6. 表格内容字体应与正文风格一致，表格宽度和列宽应保证可读性。
7. 代码、接口路径、Redis Key、MQ 队列名、数据库表名等技术标识可使用等宽字体或正文中加以区分，但全篇应保持统一。
8. 图片应清晰，不得出现大面积模糊、遮挡或与正文无关的截图。
9. 图表编号应按章节顺序统一，例如“图 3-1 本地原型系统架构图”“表 5-1 核心数据表说明”。
10. 页眉、页脚、页码可由最终排版人员统一设置。

各成员提交个人负责内容时，应保证：

1. 标题编号与本说明一致。
2. 接口、表名、Key、消息字段与项目文档一致。
3. 图片、表格、截图均提供清晰版本，并标注建议插入位置。
4. 对引用的图表在正文中进行解释。
5. 不提交与本人章节无关的重复内容。
