# 演示环境恢复指南

本文用于最终演示前把本地环境恢复到可重复验收状态。最终演示入口统一使用 Gateway：`http://localhost:8080`。

## 1. 固定演示变量

```text
ADMIN_USERNAME=admin
ADMIN_PASSWORD=admin123456
normalUser=demo-user
normalPassword=demo123456
productName=Demo 秒杀商品
stock=100
seckillPrice=99.90
baseUrl=http://localhost:8080
```

敏感配置通过 `.env` 或系统环境变量注入，不提交真实密钥。`.env.example` 只保留示例值。

## 2. 中间件启动

```powershell
docker compose up -d mysql redis rabbitmq
```

检查：

```powershell
docker ps
```

应看到 MySQL、Redis、RabbitMQ 容器处于运行状态。RabbitMQ 管理台为 `http://localhost:15672`。

## 3. MySQL 清理

演示前建议清理订单、订单明细和 MQ 日志，保留用户、商品和活动可通过接口重新创建。

```sql
DELETE FROM order_items;
DELETE FROM orders;
DELETE FROM mq_message_logs;

ALTER TABLE order_items AUTO_INCREMENT = 1;
ALTER TABLE orders AUTO_INCREMENT = 1;
ALTER TABLE mq_message_logs AUTO_INCREMENT = 1;
```

如需从零开始清理演示商品和活动：

```sql
DELETE FROM seckill_activities;
DELETE FROM product_stocks;
DELETE FROM products;
```

如需清理演示用户：

```sql
DELETE FROM users WHERE username IN ('demo-user');
```

管理员用户由 `user-service` 启动时按 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 自动初始化。

## 4. Redis 清理

演示前清理秒杀相关 key：

```text
DEL seckill:stock:{activityId}
DEL seckill:activity:{activityId}
DEL seckill:user:{activityId}:{userId}
DEL seckill:result:{activityId}:{userId}
```

如果不确定 activityId 和 userId，可用 Redis 客户端按前缀扫描后删除：

```text
SCAN MATCH seckill:*
```

## 5. RabbitMQ 清队列

在 RabbitMQ 管理台检查并清空：

```text
seckill.order.create.queue
seckill.order.create.dlq
```

演示开始前队列应无旧消息堆积。

## 6. 启动服务

推荐顺序：

```text
gateway-service
user-service
product-seckill-service
order-service
ai-service
push-service
simple-test-page
```

默认配置下业务服务不启用默认用户兜底；所有客户端请求必须经 Gateway 注入用户上下文。若仅做本地直连调试，可显式启用 `demo` profile，但最终演示不使用直连口径。

## 7. Apifox 环境

最终 Apifox 环境变量：

```text
baseUrl=http://localhost:8080
adminToken=
token=
userId=
productId=
activityId=
orderId=
```

不得把 `baseUrl` 改为 `8082`、`8083` 等服务直连地址。历史 B 组直连记录仅作为开发联调证据，不作为最终演示口径。

## 8. 恢复后执行顺序

1. 管理员登录，保存 `adminToken`。
2. 创建商品，保存 `productId`。
3. 设置商品库存为 `100`。
4. 创建秒杀活动，保存 `activityId`。
5. 普通用户注册或登录，保存 `token` 和 `userId`。
6. 测试页建立 SSE 连接。
7. 发起秒杀，确认返回 `QUEUEING`。
8. 等待 SSE 推送订单创建结果。
9. 查询秒杀结果、订单列表和订单详情。
10. 调用 AI 商品咨询。

## 9. 最终提交前补证据

当前自动化测试偏单元层，真实 MySQL、Redis、RabbitMQ 全链路仍以手工联调报告为主。最终提交前建议补一条最新记录：

```text

```
