# 接口契约核查报告

> 核查角色：成员 A  
> 核查范围：当前仓库已存在的后端控制器、统一响应、分页格式、时间与枚举口径

## 1. 核查目标

本次核查覆盖以下六项：

1. 每个接口是否以 `/api` 开头。
2. 是否都通过 Gateway 对外暴露到 `http://localhost:8080`。
3. 响应是否都有 `code/message/data`。
4. 分页字段是否是 `page/pageSize/records/total`。
5. 时间是否使用 ISO 8601。
6. 枚举是否使用大写英文。

## 2. 核查结论

### 2.1 接口路径

结论：通过。

当前已检查到的控制器路径均以 `/api` 开头：

1. `POST /api/auth/register`
2. `POST /api/auth/login`
3. `POST /api/auth/admin/login`
4. `POST /api/auth/logout`
5. `GET /api/users/me`
6. `GET /api/products`
7. `GET /api/products/{productId}`
8. `PUT /api/products/{productId}/stock`
9. `POST /api/products`
10. `POST /api/seckill/activities`
11. `GET /api/seckill/activities/{activityId}`
12. `POST /api/seckill/activities/{activityId}/orders`
13. `GET /api/seckill/activities/{activityId}/result`
14. `GET /api/orders`
15. `GET /api/orders/{orderId}`
16. `GET /api/orders/admin`
17. `POST /api/ai/products/{productId}/consult`
18. `GET /api/push/orders/subscribe`

### 2.2 Gateway 统一入口

结论：通过。

Gateway 已配置对外端口 `8080`，并路由到内部服务端口：

```text
8080 -> 8081 user-service
8080 -> 8082 product-seckill-service
8080 -> 8083 order-service
8080 -> 8084 ai-service
8080 -> 8085 push-service
```

因此对外访问口径满足“所有客户端请求必须经过 Gateway”。

### 2.3 统一响应格式

结论：通过。

当前 `common` 已统一响应为：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

失败响应也统一为：

```json
{
  "code": 401,
  "message": "未登录或 Token 无效",
  "data": null
}
```

同时保留 `queued` 语义用于秒杀排队。

### 2.4 分页字段

结论：通过。

分页响应统一使用：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "records": [],
    "page": 1,
    "pageSize": 10,
    "total": 0
  }
}
```

已检查到 `PageResponse(records, page, pageSize, total)` 口径一致。

### 2.5 时间格式

结论：部分接口未显式返回时间字段，当前未发现违背项。

文档要求时间统一使用 ISO 8601。当前秒杀活动、MQ 消息、数据库设计文档中的时间字段均以 ISO 8601 文本口径描述，后续新增返回值必须保持一致。

### 2.6 枚举命名

11. `CREATED`

## 3. 已修正问题

1. AI 咨询接口原先返回了文档外字段 `productId`、`question`，已修正为仅返回 `answer`。
2. 推送 SSE 初始事件原先发送裸 `status`，已修正为发送统一响应结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "status": "CONNECTED"
  }
}
```

## 4. 当前可继续关注的点

1. 秒杀/订单/AI 新增字段时，必须先同步 `docs/API接口契约.md`。
2. 如果后续引入真实时间字段，必须保持 ISO 8601。
3. 如果新增枚举值，必须继续使用大写英文。
4. 如果新增分页接口，必须继续沿用 `page/pageSize/records/total`。

## 5. 结论

当前已完成第一轮接口契约核查，现有实现整体符合仓库文档要求。后续新增接口或字段时，仍必须按“先文档，后代码”的规则继续维护。
