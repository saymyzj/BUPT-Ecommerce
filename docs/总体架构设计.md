# 总体架构设计

## 1. 文档目标

本文档用于冻结题目一的本地原型架构，明确服务拆分、职责边界、调用链路、目录范围和联调原则。

本文档是后续 `API接口契约`、`数据库设计`、`Redis-Key设计`、`MQ消息契约` 的上位约束文档。未写入本文档的跨服务行为，默认不允许直接开发。

## 2. 设计原则

1. 先契约，后实现。
2. 先核心链路，后边缘功能。
3. 所有客户端请求必须先经过 Gateway。
4. 业务状态以数据库为准，瞬时高并发控制以 Redis 和 MQ 为准。
5. 所有跨服务交互必须显式定义接口、事件或消息契约。
6. 所有服务必须统一响应格式与错误码。
7. 所有敏感配置必须通过环境变量注入，不得提交真实密钥。

## 3. 服务拆分

本项目建议拆分为 5 个后端服务 + 1 个前端测试页：

| 服务名 | 负责人 | 核心职责 |
| --- | --- | --- |
| `gateway-service` | A | 统一入口、路由转发、JWT 校验、基础限流、跨域、统一日志 |
| `user-service` | A | 注册、登录、注销、角色权限、JWT 签发与解析辅助 |
| `product-seckill-service` | B | 商品管理、库存管理、秒杀活动管理、Redis 预热、原子扣减 |
| `order-service` | B | MQ 消费、订单落库、订单状态查询、幂等与补偿 |
| `ai-service` | C | 商品咨询、上下文构造、LLM 调用、缓存、降级 |
| `push-service` 或 `order-service` 内推送模块 | C | SSE/WebSocket 推送订单创建结果 |
| `simple-test-page` | C | 简单测试页面，用于登录、秒杀、推送接收、AI 咨询演示 |

## 4. 职责边界

### 4.1 A 负责的边界

1. 网关统一入口
2. 用户认证与权限规范
3. 全局响应格式与错误码
4. 全局接口前缀规划
5. 联调裁定与冲突处理
6. 最终报告中的架构总览、部署与演进方案

### 4.2 B 负责的边界

1. 商品、库存、秒杀活动
2. Redis 库存预热与扣减
3. MQ 异步下单
4. 订单消费、落库、查询
5. 秒杀链路一致性与幂等

### 4.3 C 负责的边界

1. AI 商品咨询
2. 实时推送
3. 简单测试页面
4. Apifox 集合整理
5. 演示体验与视频脚本

## 6. 调用链路

### 6.1 登录链路

```text
Client
 -> Gateway
 -> user-service
 -> 返回 JWT
```

### 6.2 秒杀链路

```text
Client
 -> Gateway
 -> product-seckill-service
 -> Redis 原子扣减
 -> 投递 MQ
 -> order-service 消费
 -> MySQL 落库
 -> 推送模块发送结果
```

### 6.3 AI 咨询链路

```text
Client
 -> Gateway
 -> ai-service
 -> 商品信息查询
 -> 上下文构造
 -> 缓存命中检查
 -> LLM 调用
 -> 返回建议
```

## 7. 统一技术边界

### 7.1 Gateway 统一入口

建议路由：

```text
/api/auth/**       -> user-service
/api/users/**      -> user-service
/api/products/**   -> product-seckill-service
/api/seckill/**    -> product-seckill-service
/api/orders/**     -> order-service
/api/ai/**         -> ai-service
/api/push/**       -> push-service 或 order-service
```

Gateway 只做通用能力，不承载具体业务逻辑。

### 7.2 认证与权限

统一采用：

```text
Authorization: Bearer <token>
```

角色统一为：

```text
CUSTOMER
ADMIN
```

### 7.3 数据与中间件边界

| 中间件 | 作用 | 主要负责人 |
| --- | --- | --- |
| MySQL | 业务持久化 | B，A 参与规范 |
| Redis | 秒杀库存、缓存、限流 | B，A 参与规范 |
| RabbitMQ | 异步削峰、订单创建事件 | B |
| SSE/WebSocket | 实时推送订单结果 | C |
| LLM API | AI 咨询能力 | C |

## 8. 联调规则

1. 接口路径不得与本文档冲突。
2. 响应结构不得脱离统一格式。
3. 跨服务消息字段不得私自改名。
4. Redis key 命名不得私自变更。
5. 表结构和唯一索引变更必须先更新文档。
6. 涉及网关、认证、接口契约的变更，A 拥有最终裁定权。

## 9. 非目标

本项目当前不追求：

1. 完整电商商品全流程
2. 完整支付闭环
3. 复杂营销活动体系
4. 多端一致性客户端
5. 生产级所有边缘治理能力

本项目只聚焦可演示、可解释、可验收的高并发秒杀与智能导购主链路。
