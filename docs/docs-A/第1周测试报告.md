# 第1周测试报告

> 角色：成员 A  
> 周期：第 1 周  
> 主题：Gateway、JWT、用户认证与接口契约基础测试

## 1. 测试范围

本周测试围绕以下内容展开：

1. Gateway 是否能作为统一入口。
2. JWT 是否能签发与校验。
3. PUBLIC / CUSTOMER / ADMIN 是否能按接口分级拦截。
4. 用户认证接口是否符合契约。
5. 接口返回格式、分页格式、枚举格式是否与文档一致。
6. Swagger/OpenAPI 是否具备汇总入口。

## 2. 测试项与结果

### 2.1 Gateway 路由与鉴权

| 测试项 | 结果 | 说明 |
|---|---|---|
| `/api/auth/**` 走 Gateway | 通过 | 路由指向 `user-service` |
| `/api/users/**` 走 Gateway | 通过 | 路由指向 `user-service` |
| `/api/products/**` 走 Gateway | 通过 | 路由指向 `product-seckill-service` |
| `/api/seckill/**` 走 Gateway | 通过 | 路由指向 `product-seckill-service` |
| `/api/orders/**` 走 Gateway | 通过 | 路由指向 `order-service` |
| `/api/ai/**` 走 Gateway | 通过 | 路由指向 `ai-service` |
| `/api/push/**` 走 Gateway | 通过 | 路由指向 `push-service` |
| PUBLIC 接口放行 | 通过 | 注册、登录、管理员登录、商品列表、商品详情、秒杀活动详情可放行 |
| CUSTOMER / ADMIN 接口拦截 | 通过 | 未登录返回 `401`，权限不足返回 `403` |

### 2.2 用户认证接口

| 接口 | 结果 | 说明 |
|---|---|---|
| `POST /api/auth/register` | 通过 | 返回 `userId` |
| `POST /api/auth/login` | 通过 | 返回 `token` 和 `user` |
| `POST /api/auth/admin/login` | 通过 | 返回管理员 token 与角色 |
| `GET /api/users/me` | 通过 | 返回当前用户上下文 |
| `POST /api/auth/logout` | 通过 | 当前基线返回 `true` |

### 2.3 统一响应与分页

| 测试项 | 结果 | 说明 |
|---|---|---|
| 成功响应结构 | 通过 | `code/message/data` |
| 失败响应结构 | 通过 | `code/message/data=null` |
| 分页结构 | 通过 | `page/pageSize/records/total` |

### 2.4 枚举与时间

| 测试项 | 结果 | 说明 |
|---|---|---|
| 枚举命名 | 通过 | 使用大写英文 |
| 时间格式 | 通过 | 文档与消息契约采用 ISO 8601 口径 |

### 2.5 Swagger/OpenAPI

| 测试项 | 结果 | 说明 |
|---|---|---|
| Gateway 汇总入口 | 通过 | 已补 `/openapi/*` 路由 |
| 核心接口注解 | 通过 | 已补 `@Tag` / `@Operation` |
