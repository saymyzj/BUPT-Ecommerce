# 部署与启动指南

## 1. 目标

本文档描述本地开发环境的最低启动方式，确保 B、C 可以在同一套环境下联调。

## 2. 环境前提

### 2.1 基础依赖

建议准备：

1. JDK 17 或项目约定版本
2. MySQL 8.x
3. Redis 6.x+
4. RabbitMQ 3.x
5. Node.js（用于简单测试页时）
6. Apifox
7. Docker / Docker Compose（如采用容器化启动）

### 2.2 端口建议

| 组件 | 端口 |
| --- | ---: |
| Gateway | 8080 |
| user-service | 8081 |
| product-seckill-service | 8082 |
| order-service | 8083 |
| ai-service | 8084 |
| push-service | 8085 |
| MySQL | 3306 |
| Redis | 6379 |
| RabbitMQ | 5672 / 15672 |

端口可调整，但必须在 `README`、环境变量和 Apifox 中同步更新。

## 3. 启动顺序

推荐顺序如下：

1. MySQL
2. Redis
3. RabbitMQ
4. 后端各服务
5. Push 服务
6. 前端测试页
7. Apifox 联调

## 4. 配置方式

所有敏感信息必须通过环境变量或本地未提交配置注入。

### 4.1 建议环境变量


```text

```

```text

```

## 5. 容器化启动建议

如果项目采用 Docker Compose，建议把以下能力纳入编排：

1. MySQL
2. Redis
3. RabbitMQ
4. Gateway
5. 各微服务

若暂未容器化，至少需要在 README 中明确本机手动启动顺序和配置项。

### 5.1 推荐的可执行本地启动脚本

仓库建议提供：

```text
scripts/start-local.ps1
```

执行职责：

1. 启动 MySQL、Redis、RabbitMQ。
2. 依次启动 Gateway、用户服务、商品秒杀服务、订单服务、AI 服务、推送服务。
3. 将每个服务输出写入本地日志目录，便于排查。
4. 保持隐藏窗口启动，避免干扰联调环境。

如果暂时不使用脚本，也必须按同样顺序执行：

1. `docker compose up -d mysql redis rabbitmq`
2. 启动 `gateway-service`
3. 启动 `user-service`
4. 启动 `product-seckill-service`
5. 启动 `order-service`
6. 启动 `ai-service`
7. 启动 `push-service`
8. 打开 `simple-test-page`

## 6. 启动检查清单

启动后先确认：

1. 网关可访问
2. MySQL 可连通
3. Redis 可连通
4. RabbitMQ 管理台可打开
5. Swagger/OpenAPI 可访问
6. Apifox 可按顺序调用登录、商品、秒杀、订单、AI 接口

## 7. 联调流程

### 7.1 A 先完成

1. Gateway 路由
2. JWT 鉴权
3. 统一响应格式
4. 用户登录与权限接口

### 7.2 B 再完成

1. 商品与库存接口
2. 秒杀活动接口
3. Redis 预热
4. Lua 原子扣减
5. MQ 投递与订单消费

### 7.3 C 再完成

1. SSE/WebSocket 推送
2. AI 咨询接口
3. 测试页面
4. Apifox 集合

## 8. 本地演示建议流程

1. 启动中间件。
2. 启动 Gateway 和各服务。
3. 管理员登录。
4. 创建商品并配置库存。
5. 创建秒杀活动并预热库存。
6. 普通用户登录。
7. 建立推送连接。
8. 发起秒杀。
9. 查看排队中返回。
10. 查看订单创建成功推送。
11. 调用 AI 咨询接口。

## 9. 常见问题

### 9.1 网关不可访问

检查：

1. 端口是否冲突
2. 路由是否正确
3. 服务是否已启动

### 9.2 Redis / MQ 连接失败

检查：

1. Host/Port 是否正确
2. 用户名密码是否一致
3. 防火墙或容器网络是否可达

### 9.3 Apifox 调用失败

检查：

1. Token 是否过期
2. Base URL 是否正确
3. 接口路径是否已更新
