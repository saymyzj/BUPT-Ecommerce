# 秒杀订单实现规格

## 1. 文档目标

本文档把 `docs/秒杀订单核心链路与生产演进设计.md` 细化为可直接开发的实现规格。

本文档不修改公开接口契约，不新增公开接口。所有接口路径、请求字段、响应字段、权限以 `docs/API接口契约.md` 为准。

## 2. 技术选择

| 项目 | 选择 | 说明 |
| --- | --- | --- |
| Web 框架 | Spring Boot | 当前仓库已采用 |
| 数据库访问 | Spring Data JPA | 样板少，适合课程项目 |
| 数据库 | MySQL 8.x | 与 `docker-compose.yml` 一致 |
| Redis | RedisTemplate/StringRedisTemplate | 执行 Lua 和缓存结果 |
| MQ | Spring AMQP RabbitMQ | 对接 RabbitMQ |
| 建表方式 | SQL 脚本 | 方便复现和报告展示 |

## 3. 模块结构

### 3.1 `product-seckill-service`

建议目录：

```text
controller/
service/
repository/
entity/
dto/
redis/
mq/
config/
```

职责：

1. 商品管理。
2. 库存管理。
3. 秒杀活动管理。
4. Redis 预热。
5. Redis Lua 扣减。
6. RabbitMQ 订单消息投递。

### 3.2 `order-service`

建议目录：

```text
controller/
service/
repository/
entity/
dto/
mq/
config/
```

职责：

1. 消费秒杀订单消息。
2. 幂等检查。
3. 订单主表和明细表落库。
4. MQ 消费日志记录。
5. 订单查询。
6. Redis 秒杀结果更新。

## 4. 内部用户上下文

客户端仍然只传：

```text
Authorization: Bearer <token>
```

后端服务暂定从 Gateway 转发的内部 Header 读取用户信息：

| Header | 含义 |
| --- | --- |
| `X-User-Id` | 用户 ID |
| `X-User-Name` | 用户名 |
| `X-User-Role` | 用户角色 |

注意：

1. 这是服务间内部约定，不是客户端公共契约。
2. 该约定需要同步成员 A。
3. 业务服务不自行解析 JWT。

## 5. DTO 规格

### 5.1 创建商品

请求：

```json
{
  "name": "iPhone",
  "price": 6999,
  "description": "demo product"
}
```

响应 `data`：

```json
{
  "productId": 20001,
  "name": "iPhone",
  "price": 6999.00,
  "description": "demo product",
  "status": "ON_SALE"
}
```

### 5.2 商品详情

响应 `data`：

```json
{
  "productId": 20001,
  "name": "iPhone",
  "description": "demo product",
  "price": 6999.00,
  "status": "ON_SALE",
  "stock": {
    "totalStock": 100,
    "availableStock": 100,
    "reservedStock": 0
  }
}
```

### 5.3 设置库存

请求：

```json
{
  "stock": 100
}
```

响应 `data`：

```json
{
  "productId": 20001,
  "totalStock": 100,
  "availableStock": 100,
  "reservedStock": 0
}
```

### 5.4 创建秒杀活动

请求遵守 `docs/API接口契约.md`：

```json
{
  "productId": 20001,
  "startTime": "2026-05-25T10:00:00",
  "endTime": "2026-05-25T12:00:00",
  "seckillPrice": 99.9,
  "seckillStock": 100
}
```

响应 `data`：

```json
{
  "activityId": 1,
  "productId": 20001,
  "seckillPrice": 99.90,
  "seckillStock": 100,
  "status": "READY"
}
```

由于公开契约没有 `activityName`，实现时默认：

```text
activityName = "秒杀活动-" + productId
```

### 5.5 发起秒杀

请求：

```json
{
  "quantity": 1
}
```

响应：

```json
{
  "code": 0,
  "message": "queued",
  "data": {
    "activityId": 1,
    "status": "QUEUEING"
  }
}
```

本地原型只支持 `quantity = 1`。如果传入其他值，返回 `400 请求参数错误`。

### 5.6 查询秒杀结果

响应 `data`：

```json
{
  "activityId": 1,
  "status": "CREATED",
  "orderId": 90001,
  "message": "订单创建成功"
}
```

### 5.7 订单创建消息 DTO

严格遵守 `docs/MQ消息契约.md`：

```json
{
  "messageId": "uuid",
  "eventType": "SECKILL_ORDER_CREATE",
  "activityId": 1,
  "userId": 10001,
  "productId": 20001,
  "quantity": 1,
  "seckillPrice": 99.9,
  "orderNo": "ORD202605250001",
  "createdAt": "2026-05-25T10:00:00"
}
```

## 6. JPA 实体映射

实体字段必须对应 `docs/数据库设计.md`。

| Entity | 表 |
| --- | --- |
| `Product` | `products` |
| `ProductStock` | `product_stocks` |
| `SeckillActivity` | `seckill_activities` |
| `Order` | `orders` |
| `OrderItem` | `order_items` |
| `MqMessageLog` | `mq_message_logs` |

枚举建议：

```text
ProductStatus: ON_SALE, OFF_SALE
SeckillActivityStatus: DRAFT, READY, ONGOING, FINISHED, CANCELLED
OrderStatus: QUEUEING, CREATED, FAILED, CANCELLED, PAID
MqMessageStatus: RECEIVED, PROCESSED, FAILED
```

枚举入库统一使用大写字符串。

## 7. Service 流程

### 7.1 创建商品

```text
校验 name、price
-> 创建 products
-> 默认 status=ON_SALE
-> 返回商品信息
```

### 7.2 设置库存

```text
查询商品是否存在
-> 校验 stock >= 0
-> 若 product_stocks 已存在则更新
-> 若不存在则插入
-> total_stock=stock
-> available_stock=stock
-> reserved_stock=0
-> version 自增或初始化为 0
```

### 7.3 创建秒杀活动

```text
查询商品
-> 查询库存
-> 校验商品 ON_SALE
-> 校验活动库存 <= 商品可售库存
-> 校验 startTime < endTime
-> 插入 seckill_activities，状态 READY
-> 自动预热 Redis 活动信息和库存
-> 返回活动信息
```

### 7.4 发起秒杀

```text
读取 X-User-Id
-> 校验 quantity=1
-> 执行 Redis Lua
-> Lua 返回失败则映射错误码
-> Lua 返回成功则构造订单消息
-> 投递 RabbitMQ
-> 投递成功返回 queued
-> 投递失败回滚 Redis 并返回 20001
```

### 7.5 查询秒杀结果

```text
读取 X-User-Id
-> 查询 seckill:result:{activityId}:{userId}
-> 如果存在则返回 Redis 结果
-> 如果不存在则查询 orders(userId, activityId)
-> 如果订单存在返回 CREATED
-> 否则返回 QUEUEING 或 404
```

### 7.6 订单消费

```text
收到 MQ 消息
-> 开启数据库事务
-> 检查 messageId 是否已处理
-> 检查 orderNo 是否存在
-> 检查 userId + activityId 是否已有订单
-> 插入 mq_message_logs RECEIVED
-> 插入 orders CREATED
-> 插入 order_items
-> 更新 mq_message_logs PROCESSED
-> 提交事务
-> 更新 Redis 秒杀结果 CREATED
-> 通知推送模块
-> ACK
```

## 8. Redis Lua 规格

### 8.1 KEYS

```text
KEYS[1] = seckill:stock:{activityId}
KEYS[2] = seckill:user:{activityId}:{userId}
KEYS[3] = seckill:result:{activityId}:{userId}
KEYS[4] = seckill:activity:{activityId}
```

### 8.2 ARGV

```text
ARGV[1] = now，例如 2026-05-25T10:01:00
ARGV[2] = userFlagTtlSeconds
ARGV[3] = resultTtlSeconds
```

### 8.3 Lua 返回码

| 返回码 | 含义 | HTTP 映射 |
| --- | --- | --- |
| `0` | 成功扣减并进入队列 | `queued` |
| `1` | 库存不足 | `10001` |
| `2` | 用户重复抢购 | `10004` |
| `3` | 活动未开始 | `10002` |
| `4` | 活动已结束 | `10003` |
| `5` | 活动不存在 | `404` |

### 8.4 成功写入的结果

```json
{
  "status": "QUEUEING",
  "orderId": null,
  "message": "queued"
}
```

### 8.5 MQ 投递失败回滚

如果 MQ 投递失败：

```text
INCR seckill:stock:{activityId}
DEL seckill:user:{activityId}:{userId}
SET seckill:result:{activityId}:{userId} = FAILED
```

## 9. RabbitMQ 配置规格

| 项 | 值 |
| --- | --- |
| Exchange | `seckill.order.exchange` |
| Exchange 类型 | `topic` |
| Queue | `seckill.order.create.queue` |
| Dead Letter Queue | `seckill.order.create.dlq` |
| Routing Key | `seckill.order.create` |
| 消息持久化 | 是 |
| 消费确认 | 手动 ACK |

消费者处理：

1. 成功落库后 ACK。
2. 重复消息已确认处理后 ACK。
3. 临时异常 NACK 并重试。
4. 多次失败后进入死信队列。

## 10. 事务边界

订单消费中的以下操作必须在同一个 MySQL 事务中：

```text
插入/检查 mq_message_logs
插入 orders
插入 order_items
更新 mq_message_logs 状态
```

Redis 结果更新不在 MySQL 事务内。若 Redis 更新失败，以 MySQL 订单为准，后续可通过补偿任务回刷 Redis。

## 11. 异常处理映射

| 场景 | 返回或处理 |
| --- | --- |
| 商品不存在 | `404 资源不存在` |
| 库存不足 | `10001 库存不足` |
| 活动未开始 | `10002 秒杀活动未开始` |
| 活动已结束 | `10003 秒杀活动已结束` |
| 重复抢购 | `10004 用户已参与该活动` |
| MQ 投递失败 | `20001 MQ 投递失败`，并回滚 Redis |
| 重复消费 | 不创建新订单，直接 ACK |
| 订单落库失败 | 记录失败，重试或死信 |

## 12. 与成员 A/C 对接

### 12.1 与成员 A

需要确认：

1. Gateway 是否注入 `X-User-Id`、`X-User-Name`、`X-User-Role`。
2. ADMIN 和 CUSTOMER 权限是否由 Gateway 拦截。
3. 是否允许服务内做二次角色校验。

### 12.2 与成员 C

需要提供：

1. 商品详情字段。
2. 活动详情字段。
3. 秒杀返回 `queued` 样例。
4. 查询结果返回样例。
5. 订单成功事件字段。
