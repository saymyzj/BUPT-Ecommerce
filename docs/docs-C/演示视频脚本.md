# 演示视频脚本

## 1. 视频目标

控制在 3-5 分钟，证明系统具备：

1. Gateway 统一入口。
2. JWT 登录与权限控制。
3. 商品、库存、秒杀活动准备。
4. Redis + MQ 异步秒杀订单链路。
5. 订单创建结果实时推送。
6. AI 商品咨询和降级标识。
7. Apifox 与测试页可复现。

## 2. 录制前准备

1. 启动 MySQL、Redis、RabbitMQ。
2. 依次启动：
   - `gateway-service`
   - `user-service`
   - `product-seckill-service`
   - `order-service`
   - `ai-service`
   - `push-service`
3. 打开 `simple-test-page/index.html`。
4. 打开 RabbitMQ 管理台或订单服务日志窗口。
5. 打开 Apifox 环境变量页。

## 3. 推荐时间线

### 0:00 - 0:30 项目入口

展示 Gateway 地址：

```text
http://localhost:8080
```

说明所有客户端请求都走 Gateway。

### 0:30 - 1:20 管理员准备

1. 管理员登录。
2. 创建商品。
3. 设置库存。
4. 创建秒杀活动。
5. 展示 `productId` 和 `activityId`。

### 1:20 - 2:20 用户秒杀和异步下单

1. 普通用户注册或登录。
2. 建立推送连接，显示 `CONNECTED`。
3. 发起秒杀。
4. 强调秒杀接口只返回：

```text
queued / QUEUEING
```

5. 切到 RabbitMQ 或订单服务日志，展示订单消息被消费。

### 2:20 - 3:10 实时推送验证

1. 回到测试页，展示 `ORDER_CREATED` 推送。
2. 展示推送中的 `orderId`。
3. 调用订单详情接口。
4. 对比订单详情和推送事件中的 `activityId`、`userId`、`status`。

### 3:10 - 3:50 AI 咨询

1. 输入商品问题。
2. 调用 `POST /api/ai/products/{productId}/consult`。
3. 如果配置了 LLM，展示 `SUCCESS` 回答。
4. 如果没有配置 LLM，展示 `30001` 和 `status=FALLBACK`，说明这是明确降级，不是假回答。

### 3:50 - 4:30 Apifox 和总结

1. 展示 Apifox 8 个分组。
2. 展示环境变量。
3. 简述生产演进：
   - Gateway 多实例
   - Redis Sentinel / Cluster
   - RabbitMQ 集群
   - MySQL 主从
   - AI 缓存、限流、排队、降级

## 4. 必须避免

1. 不展示静态写死订单成功。
2. 不把秒杀接口的 `QUEUEING` 解释为成单。
3. 不绕过 Gateway 直连后端服务。
4. 不展示真实密钥、Token 长串可适当打码。
