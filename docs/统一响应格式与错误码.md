# 统一响应格式与错误码

## 1. 目标

全项目所有 HTTP 接口必须返回统一结构，避免前端、Apifox、演示脚本和跨服务调用出现多套格式。

## 2. 统一响应格式

### 2.1 成功响应

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

### 2.2 失败响应

```json
{
  "code": 400,
  "message": "请求参数错误",
  "data": null
}
```

## 3. 字段定义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | number | 业务状态码，`0` 表示成功 |
| `message` | string | 人类可读说明 |
| `data` | any | 业务数据，失败时可为空 |

## 4. 分页响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "records": [],
    "page": 1,
    "pageSize": 10,
    "total": 100
  }
}
```

## 5. 推荐错误码

### 5.1 通用错误码

| code | message | 含义 |
| ---: | --- | --- |
| 0 | success | 成功 |
| 400 | 请求参数错误 | 参数缺失、格式错误、校验失败 |
| 401 | 未登录或 Token 无效 | 未携带 Token、Token 过期、Token 非法 |
| 403 | 无权限 | 角色不匹配或接口权限不足 |
| 404 | 资源不存在 | 查询对象不存在 |
| 409 | 业务冲突 | 重复秒杀、重复提交、状态冲突 |
| 429 | 请求过于频繁 | 限流触发 |
| 500 | 服务器内部错误 | 未预期异常 |

### 5.2 业务错误码

| code | message | 含义 | 主要归属 |
| ---: | --- | --- | --- |
| 10001 | 库存不足 | 秒杀库存不足 | B |
| 10002 | 秒杀活动未开始 | 活动开始前请求 | B |
| 10003 | 秒杀活动已结束 | 活动结束后请求 | B |
| 10004 | 用户已参与该活动 | 重复抢购 | B |
| 20001 | MQ 投递失败 | 秒杀消息发送失败 | B |
| 30001 | AI 服务暂不可用 | LLM 调用失败或降级 | C |

## 6. 典型返回示例

### 6.1 登录成功

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "token": "jwt-token"
  }
}
```

### 6.2 秒杀排队中

```json
{
  "code": 0,
  "message": "queued",
  "data": {
    "activityId": 1,
    "status": "QUEUEING"
  }
}
```

### 6.3 AI 降级返回

```json
{
  "code": 30001,
  "message": "AI 服务暂不可用",
  "data": {
    "answer": "当前咨询服务繁忙，建议先查看商品详情页信息。"
  }
}
```

## 7. 异常处理规则

1. 参数校验失败返回 `400`。
2. 未登录返回 `401`。
3. 权限不足返回 `403`。
4. 业务规则冲突返回 `409` 或业务码。
5. 未捕获异常统一映射为 `500`。
6. 不允许直接把 Java、Python、数据库原始异常栈返回给前端。

## 8. 时间与枚举约定

1. 时间统一使用 ISO 8601 文本格式。
2. 枚举字段统一使用大写英文字符串。
3. 状态值不得在不同服务里用不同命名。

## 9. 文档约束

如果某接口返回结构不是本文档定义的格式，必须视为契约不一致并优先修正。
