# 最终验收主链路说明

本文用于最终验收、答辩和演示视频串讲。最终演示口径：所有客户端请求统一从 Gateway 进入，Base URL 固定为 `http://localhost:8080`。内部接口 `/api/orders/internal/**` 不进入客户端演示集合。

## 1. 主链路总览

```text
管理员登录
 -> 创建商品
 -> 设置库存
 -> 创建秒杀活动
 -> 普通用户注册/登录
 -> 建立 SSE 推送连接
 -> 发起秒杀
 -> Redis Lua 原子扣减
 -> RabbitMQ 投递订单创建消息
 -> order-service 消费消息并落库
 -> push-service 推送订单创建结果
 -> 用户查询订单
 -> AI 商品咨询
```

## 2. 演示步骤

### 2.1 管理员准备商品和活动

1. `POST /api/auth/admin/login`
   - 使用 `ADMIN_USERNAME` / `ADMIN_PASSWORD`。
   - 保存 `adminToken`。
2. `POST /api/products`
   - Header：`Authorization: Bearer {{adminToken}}`。
   - 创建演示商品，记录 `productId`。
3. `PUT /api/products/{{productId}}/stock`
   - 设置演示库存，例如 `100`。
4. `POST /api/seckill/activities`
   - 创建秒杀活动，记录 `activityId`。
   - 创建后服务会预热 Redis 活动信息和秒杀库存。

### 2.2 用户进入秒杀链路

1. `POST /api/auth/register`
   - 注册普通用户；如用户已存在，可直接登录。
2. `POST /api/auth/login`
   - 保存 `token` 和 `userId`。
3. `GET /api/push/orders/subscribe`
   - Header：`Authorization: Bearer {{token}}`。
   - 建立 SSE 连接，等待订单结果事件。
4. `POST /api/seckill/activities/{{activityId}}/orders`
   - Header：`Authorization: Bearer {{token}}`。
   - 返回 `message=queued`、`status=QUEUEING` 表示已进入异步订单链路。

### 2.3 异步订单和推送

1. 秒杀服务通过 Redis Lua 一次性完成活动校验、库存扣减、重复参与校验、用户参与标记和排队结果写入。
2. 秒杀服务向 RabbitMQ 投递 `SECKILL_ORDER_CREATE` 消息。
3. 订单服务消费消息，按 `messageId`、`orderNo`、`userId + activityId` 幂等落库。
4. 订单服务写回 `seckill:result:{activityId}:{userId}`。
5. 订单服务调用推送服务，推送当前用户自己的订单创建结果。

### 2.4 用户复核订单和 AI 咨询

1. `GET /api/seckill/activities/{{activityId}}/result`
   - 查看秒杀结果，成功时能看到 `orderId` 和 `orderNo`。
2. `GET /api/orders?page=1&pageSize=10`
   - 查看当前用户订单列表。
3. `GET /api/orders/{{orderId}}`
   - 查看订单详情；服务内会二次校验只能查本人订单。
4. `POST /api/ai/products/{{productId}}/consult`
   - AI 服务基于商品详情上下文回答。
   - 未配置 LLM 或调用失败时返回 `code=30001` 和降级回答，不伪装为真实 AI 成功。

## 3. 验收观察点

1. Gateway：所有 Apifox 和测试页请求均使用 `http://localhost:8080`。
2. 权限：管理员接口必须带管理员 token；普通用户不能创建商品、设置库存或查管理员订单。
3. Redis：库存 key 被扣减，用户参与 key 和结果 key 被写入。
4. RabbitMQ：订单创建消息进入消费队列并被消费。
5. MySQL：`orders`、`order_items`、`mq_message_logs` 出现对应记录。
6. SSE：只有当前用户收到自己的订单结果。
7. AI：成功时返回回答；失败时明确返回 `30001` 降级。

## 4. 当前自动化验证边界

当前自动化测试主要覆盖单元层和服务内契约，包括 Gateway 策略、用户持久化、秒杀 Lua 返回码映射、MQ 幂等、订单权限、AI 契约和服务内权限二次校验。

真实 MySQL、Redis、RabbitMQ 的端到端联调仍需在最终提交前按 `docs/演示环境恢复指南.md` 再跑一轮，并把日期、命令、截图或结果补充到阶段报告中。
