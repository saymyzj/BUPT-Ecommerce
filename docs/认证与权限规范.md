# 认证与权限规范

## 1. 目标

本文档冻结 JWT、角色、鉴权、注销和权限判定规则，作为 A 组负责的统一认证规范。

## 2. 基本约定

### 2.1 鉴权头

```text
Authorization: Bearer <token>
```

### 2.2 角色定义

| 角色 | 含义 | 典型权限 |
| --- | --- | --- |
| `CUSTOMER` | 普通用户 | 浏览商品、发起秒杀、查询订单、使用 AI 咨询 |
| `ADMIN` | 管理员 | 商品管理、库存配置、活动创建、订单查询 |

## 3. JWT 规范

### 3.1 载荷建议

```json
{
  "userId": 10001,
  "username": "alice",
  "role": "CUSTOMER",
  "iat": 1710000000,
  "exp": 1710003600
}
```

### 3.2 必备字段

| 字段 | 说明 |
| --- | --- |
| `userId` | 用户 ID |
| `username` | 用户名 |
| `role` | 用户角色 |
| `iat` | 签发时间 |
| `exp` | 过期时间 |

### 3.3 签名规则

1. 使用统一 `JWT_SECRET`。
2. 所有服务仅信任网关和认证服务签发的 token。
3. token 不得明文写入仓库。

## 4. Token 生命周期

建议：

1. 登录后签发 token。
2. token 具备固定有效期。
3. 过期后返回 `401`。
4. 注销后应视实现选择失效处理。

## 5. 权限判定规则

### 5.1 PUBLIC

无需登录即可访问。

### 5.2 CUSTOMER

登录后普通用户可访问。

### 5.3 ADMIN

仅管理员可访问。

## 6. 网关鉴权职责

Gateway 至少应完成：

1. 解析 token。
2. 校验签名和有效期。
3. 注入用户上下文。
4. 拦截无权限请求。
5. 对管理接口做角色校验。

## 7. 服务端上下文

服务在处理请求时可使用以下上下文信息：

```json
{
  "userId": 10001,
  "username": "alice",
  "role": "CUSTOMER"
}
```

当前基线约定：

1. 服务端只信任 Gateway 注入的上下文头。
2. `user-service` 的 `/api/users/me` 不直接回退解析客户端侧 `Authorization`。
3. 直连内部服务的请求如果缺少 Gateway 注入头，统一视为未登录。

## 8. 接口权限分级

### 8.1 PUBLIC 接口

1. 登录
2. 注册
3. 商品列表
4. 商品详情
5. 秒杀活动详情

### 8.2 CUSTOMER 接口

1. 发起秒杀
2. 查询秒杀结果
3. 查询订单
4. AI 咨询
5. 建立推送连接

### 8.3 ADMIN 接口

1. 创建商品
2. 设置库存
3. 创建秒杀活动
4. 管理员订单查询

## 9. 注销与黑名单

注销功能可以采用以下任一种实现方式：

1. 客户端删除本地 token。
2. 服务端记录 token 黑名单。
3. 记录用户注销时间，校验 `iat`。

若暂不实现黑名单，也必须在文档中明确“注销仅清除客户端态”。

当前课程原型的用户密码使用 SHA-256 摘要后存入 `password_hash`，可满足不保存明文密码的演示要求，但不应表述为生产级密码安全方案。生产环境应迁移到 BCrypt、Argon2 等带盐且具备计算成本控制的密码哈希算法。

## 10. 统一错误返回

认证相关失败统一使用：

1. `401` 未登录或 token 无效
2. `403` 无权限

## 11. 变更控制

以下内容变更必须先更新本文档：

1. 角色名称
2. token 载荷字段
3. token 有效期
4. 权限判定规则
5. 网关拦截策略
6. 注销策略
