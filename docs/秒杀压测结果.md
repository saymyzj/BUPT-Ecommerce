# 秒杀压测结果

## 1. 目标

使用 `scripts/seckill-load-test.js` 验证 100 件秒杀库存面对 10000 个不同用户并发请求时不超卖、不重复下单，并保留可复现的答辩证据。

## 2. 执行命令

默认 Gateway 模式：

```powershell
$env:MYSQL_CONTAINER='bupt-ecommerce-mysql-load'
$env:REDIS_CONTAINER='campusmast-redis'
$env:WAIT_SECONDS='60'
$env:USER_PREP_CONCURRENCY='50'
node scripts\seckill-load-test.js
```

说明：

1. `MODE` 未设置时默认为 `gateway`。
2. 客户端请求统一走 `http://localhost:8080`。
3. 管理员和 10000 个压测用户均通过登录接口获取 JWT。
4. `MYSQL_CONTAINER` 和 `REDIS_CONTAINER` 是本机验证环境的容器名覆盖项。

内部核心链路压测模式仍保留，但只用于服务内快速验证：

```bash
MODE=internal BASE_URL=http://localhost:8082 node scripts/seckill-load-test.js
```

## 6. 结论

本轮 Gateway 模式压测中，10000 个不同用户同时请求 100 件秒杀库存：

1. MySQL 最终订单数为 `100`，未超过库存。
2. Redis 秒杀库存最终为 `0`，库存扣减与订单结果一致。
3. 重复订单数为 `0`，`orders(user_id, activity_id)` 幂等约束有效。
4. 脚本自动断言通过，输出 `verificationStatus=PASS`。

响应统计中存在 `500` 和 `NETWORK_ERROR`，说明本机课程原型在 10000 同时连接下仍有入口连接饱和或客户端网络错误；但核心秒杀不变量已经成立：不超卖、不重复下单、库存归零、订单数等于库存数。

## 7. 脚本修复记录

首次执行时发现脚本使用 `toISOString()` 生成 UTC 时间，后端按本地 `LocalDateTime` 解析后导致活动时间落在过去，表现为大量 `10003` 活动已结束。已修复为本地时间格式 `yyyy-MM-ddTHH:mm:ss` 后重新执行并得到上述 PASS 结果。
